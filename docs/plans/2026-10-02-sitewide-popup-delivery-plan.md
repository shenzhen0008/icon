# 全站待处理弹窗展示改造方案

## 背景

管理员批量发送弹窗后，活动与目标用户记录会写入 `popup_campaigns` 和 `popup_campaign_user`。用户端目前只在首页的 `resources/views/components/home/stats.blade.php` 中每 15 秒轮询 `/home-summary`，因此用户停留在其他页面时不会检查待处理弹窗。

现有视图各自维护完整 HTML 文档，没有统一 Blade 主布局；多数业务页及登录、注册页均复用 `x-nav.top`。方案应复用现有公共组件入口，避免逐页复制弹窗实现。覆盖范围为使用 `x-nav.top` 的用户端页面；不包含 Filament 管理后台及未挂载该组件的独立页面。

## 目标

1. 登录用户打开覆盖范围内的业务页面后，检查最新一条待处理活动，未命中本地防重记录时展示。
2. 移除首页弹窗对 15 秒统计轮询的依赖；首页统计轮询仍可保留用于统计数字。
3. 保持现有活动、目标用户、回执数据模型及确认语义。
4. 一次页面加载至多检查一次；同一用户在同一浏览器存储未清除期间，同一活动不因普通页面切换而重复展示。存储不可用及跨标签页同时首次查询的例外见已知边界。

## 建议方案

新增一个受 `auth` 保护的轻量待处理弹窗读取接口，例如 `GET /popup/pending`，复用 `PopupFeedService::resolveForUser()` 的筛选逻辑。接口返回单条待处理活动或 `null`，不新增数据库表或依赖。

本次保持现有“最新活动优先”的筛选规则：按 `created_at`、`id` 倒序返回有效期内最新一条未确认活动，不承诺逐条送达全部待处理活动。最新活动已展示但未确认时，仍会由服务端返回，并可能遮挡更早活动；不通过客户端排除参数或循环查询绕过该规则。

新增 `GET /popup/pending` 接口，响应形状为 `{ "popup": {...}|null }`，不接收活动 ID 等目标参数；目标用户完全由服务端认证会话确定。控制器采用 invokable 风格并构造注入 `PopupFeedService`，与 `HomeSummaryFeedController` 保持一致。接口放在 `routes/web.php` 现有 `auth` 组中，并显式返回 `Cache-Control: private, no-store`，避免缓存用户私有弹窗数据。

将弹窗容器及检查脚本封装为 Blade 组件，**二者一起挂到 `x-nav.top`，并确保位于 `main` 之外**；不得再挂到 `x-nav.mobile`。脚本以 header 中已有的 `data-page-cache-context` 判断登录态和读取用户上下文：`guest` 时不发请求，`user:{id}` 时请求接口，并将用户上下文纳入本地防重键。无需在每个页面额外埋点。

页面缓存通过 `root.outerHTML` 替换 main，导航组件不会随页面替换，因此组件监听 `page-cache:restored`，首次 DOM ready 和每次自定义页面缓存恢复时触发检查。组件内使用一个 in-flight 布尔锁；请求期间的恢复事件直接跳过，不排队补查。已有弹窗打开时跳过检查，不覆盖当前内容。普通账号切换沿用完整页面加载，不增加请求完成后的账号上下文复核。

防重记录在组件初始化时读取，通过现有跨标签页 `storage` 事件更新内存记录；展示前只检查内存记录，不额外读取存储，不承诺跨标签页原子互斥。命中时使用公共导航组件提供的稳定弹窗 DOM 容器渲染，沿用 `/popup/{campaign}/shown|confirm` 回执接口；`dismiss` 接口保持兼容，本次不新增关闭入口。没有活动时不轮询。

防重记录按 `user:{id}` 分隔，继续使用 `localStorage`。旧键不迁移、不清理，换键后历史未确认活动可能再次展示。存储读写失败时继续使用当前文档的内存记录，不增加单独的存储降级机制。

首页 `stats` 组件保留统计数字刷新，但移除其中的弹窗 DOM、弹窗回执和弹窗轮询处理。`HomeSummaryService` 同步移除 popup 解析，`/home-summary` 不再返回 `popup` 字段，让统计接口保持职责单一。将 `tests/Feature/PopupPush/PopupPushFeedTest.php` 中依赖 `/home-summary` popup 字段的用例迁移到新接口。

## 关键实现要求

1. 服务端只从当前认证用户身份读取目标用户 ID；匿名请求不得读取其他用户的活动。
2. 弹窗正文继续以 `textContent` 渲染，禁止将管理员输入内容作为 HTML 插入。
3. 保持当前“仅确认”的用户端交互：无关闭按钮，禁止 Escape 和点击遮罩关闭；本次不按 `requires_ack` 新增关闭分支。点击确认后等待回执成功再关闭；必须检查 HTTP 成功状态和响应 `ok`，失败时保留弹窗、显示简短错误并允许重试，提交期间禁止重复提交。确认成功后该活动不再由服务端返回。
4. 前端防重键使用 header 的 `data-page-cache-context`（`user:{id}`），避免同一浏览器切换账号时一个账号的本地展示记录屏蔽另一个账号。
5. 待读取接口失败时静默处理，不影响页面主体；用户下一次加载或通过自定义页面缓存恢复页面时再次检查。读取失败不得写入已展示记录；仅在弹窗成功打开后记录已展示。确认请求失败按第 3 条处理，不得静默视为确认成功。`shown` 回执失败不影响展示，本次不新增后台重试机制。
6. 组件仅通过首次 DOM ready 和 `page-cache:restored` 触发检查；按建议方案跳过并发请求并保护已打开弹窗。每个页面的 `x-nav.top` 只挂载一次组件，且位于 main 外，由页面结构保证监听器只初始化一次；不增加全局初始化标记或监听器管理层。
7. 不引入 WebSocket、广播、队列或新依赖；本方案保证“打开页面时检查”，不承诺用户停留页面期间实时推送。
8. 页面缓存的 `guest` 上下文不发请求；路由仍由 `auth` 中间件保护。匿名普通 HTML 请求重定向至登录页（302），带 `Accept: application/json` 的匿名请求返回 401。前端读取明确发送 JSON 请求头，遇到 401 或非预期响应时按读取失败处理，不渲染登录页 HTML。

## 影响范围

- 新增 `app/Modules/PopupPush/Http/Controllers/PendingPopupController.php`，invokable 控制器，构造注入 `PopupFeedService`。
- 更新 `routes/web.php`，在现有 `auth` 组中新增读取路由，并与三条回执路由并列。
- 新增 `resources/views/components/popup-push/pending.blade.php`，封装弹窗容器、检查脚本、防重和回执处理。
- 更新 `resources/views/components/nav/top.blade.php`，挂载 `x-popup-push.pending`，确保容器和脚本位于 main 之外；不挂入 `x-nav.mobile`。
- 更新 `resources/views/components/home/stats.blade.php`，分离弹窗职责与首页统计刷新。
- 更新 `app/Modules/Home/Services/HomeSummaryService.php`，移除 popup 解析，`/home-summary` 不再返回 popup 字段。
- 更新 `config/client_env.php`，将 `popup/pending` 加入 `persist_excluded_paths`，避免高频请求写入 `probe-log.jsonl`。
- 迁移并更新 `tests/Feature/PopupPush/PopupPushFeedTest.php` 中依赖 `/home-summary` popup 字段的用例，覆盖新接口；前端核心自动化检查归入 `tests/Frontend/PopupPush/`，复用现有测试工具，不为浏览器边界场景搭建新测试框架或新增依赖。

本方案不改数据库结构，因此不需要同步修改 `database/sql/mvp_schema.sql`。

## 验收标准

1. 登录用户在首页、个人中心、产品、充值、订单等业务页加载后，均可检查发给自己的最新一条待处理活动；没有防重记录时正常展示。
2. 非目标用户得到 `{ "popup": null }`；匿名 HTML 请求返回 302，匿名 JSON 请求返回 401，匿名登录及注册页不会发起该请求。
3. 已确认活动不会再次返回；确认失败时弹窗保持打开并可重试，成功后关闭。不同 `requires_ack` 值均保持本次仅确认交互。
4. 同一用户切换到站内其他页面，不会因重复初始化而重复弹出同一活动；账号间防重记录隔离。
5. 每次真实页面加载或自定义页面缓存恢复至多发起一次待处理查询；in-flight 时跳过事件，弹窗打开时跳过检查，不产生并发或覆盖；首页统计轮询不再负责弹窗投递。
6. 正文按纯文本安全渲染；读取接口不可用时页面其他功能照常工作。
7. 最新活动 B 已展示但未确认时，后续查询仍返回 B，客户端跳过展示；B 确认后，下次页面检查可返回较早活动 A。本次不在确认后自动追加查询。

## 验证

自动化检查聚焦以下核心场景：

- 接口：目标用户读取成功、非目标用户返回 null、匿名 HTML/JSON 请求分别返回 302/401、已确认及无效状态或有效期外活动不返回、响应包含 `Cache-Control: private, no-store`；传入其他用户 ID 不改变当前认证用户的查询范围。
- 多活动：验证最新活动遮挡旧活动的既定边界，以及确认最新活动后下次检查返回较早活动。
- 前端核心流程：首次加载、自定义缓存恢复触发检查；请求未完成时再次恢复不并发，已打开弹窗不被覆盖；同一账号同一活动不重复展示，账号间防重键隔离。
- 回执和安全：确认返回 4xx/5xx、网络失败或非预期响应时保持弹窗并允许重试；成功后关闭；两个 `requires_ack` 值均禁止非确认关闭；正文包含 HTML 时仅显示文本。
- 接口解耦：`/home-summary` 不再包含 popup 字段。

手工验收使用一组简短场景：在首页及主要业务页检查实际展示与 main 外挂载；通过自定义缓存切换页面，确认防重且统计刷新正常；退出后换账号确认隔离，匿名登录及注册页不发读取请求；用两个标签页检查 `storage` 同步；禁用存储后确认页面和当前文档防重仍可用。不要求跨标签页竞态、旧键处理或原生 BFCache 恢复的完整自动化矩阵。

读取接口无业务输入，不为其虚构无效输入路径；已有回执接口保留非目标用户和无效活动 ID 的拒绝用例。执行相关前端检查、`php artisan test` 和 `npm run build`，记录手工验收结果；实际展示不能仅以 Blade 字符串断言代替。交付说明列出变更文件、执行命令、验证结果及已知限制。

## 已知边界

该方案在用户下一次打开/切换到业务页面时检查。若用户一直停留在单个页面，期间新发送的弹窗要等下次页面加载或缓存页面切换才会显示；若后续需要在停留页面时即时送达，再单独评估广播或轻量轮询。

本次不监听 `pageshow`，浏览器原生后退缓存（BFCache）恢复不保证重新检查；如实际出现后退恢复漏投需求，再补充该生命周期处理。同一文档内局部登录或账号切换也不在本次范围内。

已展示但未确认的活动仍会被服务端返回，浏览器 `localStorage` 防重逻辑负责避免普通跨页面重复弹出；这包含展示后离开页面、刷新或关闭标签页的情况，并非提供弹窗关闭按钮。用户换设备、清除存储或首次使用新防重键后，可能再次看到该活动。

最新一条未确认活动可能持续遮挡更早活动；本次保持这一现有行为，不保证全部活动逐条送达。若后续要求完整投递，应单独调整筛选和回执语义。

`storage` 事件不能提供跨标签页原子互斥，两个标签页同时首次检查仍可能重复展示。localStorage 不可用时仅保证当前文档内防重，真实重新加载后可能再次展示。确认失败后离开页面，本地已展示记录也可能阻止下次展示；本次提供当前弹窗内重试，不承诺持久化确认重试。`shown` 回执失败可能使服务端展示统计缺失。
